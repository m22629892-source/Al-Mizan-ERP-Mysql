# تشغيل الميزان ERP على MySQL — Windows وMySQL Workbench

هذه نسخة محوّلة من SQLite إلى MySQL. الخادم يتصل بـMySQL؛ برنامج Workbench واجهة لإدارة السيرفر فقط.

الإعدادات المطابقة للصورة: MySQL Server 8.0.28، المضيف 127.0.0.1، بورت قاعدة البيانات 3306. بورت تطبيق الويب مستقل وهو 4000. نسخة Node المحددة في المشروع: 26.13.0.

## 1. إنشاء القاعدة من MySQL Workbench

1. فك ZIP في مجلد جديد، ولا تستبدل نسختك القديمة أو ملف almizan.db.
2. افتح Workbench ثم اتصال Local instance MySQL80 الموجود عندك.
3. اختر File → Open SQL Script، وافتح `database/almizan_mysql_demo.sql` من مجلد النسخة الجديدة.
4. تأكد أنك تريد قاعدة جديدة اسمها `almizan`. لو الاسم مستخدم لبيانات مهمة، غيّر الاسم في سطري CREATE DATABASE وUSE وفي .env قبل التنفيذ، أو استخدم سيرفر تجريبي مستقل.
5. ألغِ أي تحديد للنص، ثم اختر Query → Execute (All or Selection)، أو اضغط زر البرق الذي ينفذ السكربت بالكامل. ليس زر تنفيذ الاستعلام الحالي فقط.
6. انتظر ظهور علامات النجاح في Action Output. لو ظهر خطأ توقف عنده؛ لا تعتبر السكربت اكتمل.
7. في يسار الشاشة افتح تبويب Schemas بجانب Administration، ثم اضغط Refresh. ستجد `almizan` وبداخلها 55 جدولاً.

الملف التجريبي يتضمن الجداول والبيانات التجريبية. لا تنفذه فوق بيانات فعلية، ولا تعِد تنفيذه على نفس القاعدة المعبأة: يحتوي INSERT عاديًا كي يظهر خطأ بدل تجاهل التعارضات.

`database/almizan_mysql.sql` بديل لإنشاء الهيكل فقط، ولا تنفذ الملفين معًا. عند اختيار الهيكل فقط يمكنك لاحقًا تشغيل `npm run db:init -- --demo` على قاعدة تجريبية لإنشاء البيانات.

## 2. إنشاء مستخدم اتصال للتطبيق

افتح `database/create_app_user.sql` في Workbench، واستبدل `CHANGE_THIS_LOCAL_PASSWORD` بكلمة مرور تختارها، ثم نفذه بحساب root.

المستخدم الناتج `almizan_app` له صلاحيات على قاعدة almizan فقط. لا توجد حاجة إلى استخدام حساب root في تشغيل التطبيق. لو المستخدم موجود من قبل فلن تتغير كلمة مروره تلقائيًا؛ يوجد مثال ALTER USER داخل الملف لتغييرها صراحةً عند الحاجة.

## 3. إعداد البرنامج

داخل المجلد الذي يحتوي package.json، انسخ `.env.example` إلى `.env`. تأكد أنه ليس `.env.txt`. من CMD:

```bat
copy .env.example .env
notepad .env
```

اجعل محتواه:

```dotenv
MYSQL_HOST=127.0.0.1
MYSQL_PORT=3306
MYSQL_DATABASE=almizan
MYSQL_USER=almizan_app
MYSQL_PASSWORD="اكتب_كلمة_المرور_التي_اخترتها"
MYSQL_POOL_SIZE=10
PORT=4000
NODE_ENV=development
SEED_DEMO_DATA=false
```

علامتا الاقتباس مفيدتان إذا احتوت كلمة المرور على # أو مسافات. لا ترفع ملف .env إلى GitHub ولا تشارك كلمة المرور.

## 4. التثبيت والتشغيل

افتح CMD جديدًا داخل مجلد النسخة المحولة:

```bat
node -v
npm ci
npm run db:check
npm run dev
```

انتظر نجاح كل أمر قبل التالي. بعد نجاح db:check سيظهر اسم القاعدة وإصدار MySQL والبورت. افتح http://localhost:4000 واترك نافذة CMD مفتوحة.

دخول البيانات التجريبية فقط:

- اسم المستخدم: `owner`
- كلمة المرور: `admin123`

غيّر كلمة المرور من إدارة المستخدمين قبل إتاحة النسخة لآخرين. البيانات الحالية نموذجية ولا تثبت امتثالًا ضريبيًا أو جاهزية للاستخدام المالي الفعلي.

لا حاجة إلى فتح بورت قاعدة البيانات 3306 للإنترنت عند تشغيل MySQL والبرنامج على نفس الكمبيوتر. MySQL خدمة يجب أن تكون شغالة؛ إغلاق Workbench لا يوقف الخدمة عادةً.

## 5. لو حدث خطأ

- `ECONNREFUSED`: تأكد من تشغيل خدمة MySQL80 ومن أن MYSQL_PORT يطابق البورت الظاهر في Workbench.
- `ER_ACCESS_DENIED_ERROR`: اسم المستخدم أو كلمة المرور أو صلاحيات الحساب غير صحيحة؛ راجع create_app_user.sql و.env.
- `ER_BAD_DB_ERROR`: القاعدة غير موجودة أو اسمها مختلف.
- `EADDRINUSE`: غيّر PORT في .env إلى 4001 مثلًا وأعد تشغيل البرنامج.
- `EPERM` عند npm ci: أغلق البرنامج وVS Code، واحذف node_modules من النسخة الجديدة فقط ثم أعد التثبيت. احتفظ بـpackage-lock.json.
- إذا ظهر better-sqlite3 أثناء npm ci فأنت غالبًا داخل مجلد النسخة القديمة؛ هذه النسخة لا تعتمد على تلك المكتبة.

## 6. نقل بيانات SQLite الموجودة عندك (اختياري)

الملف SQL التجريبي ليس نسخة من بياناتك الشخصية. إن كانت لديك بيانات فعلية، احتفظ بملف SQLite الأصلي وأوقف البرنامج القديم أولًا للحصول على نسخة مكتملة، بما فيها أي WAL قائم. لا تنسخ ملف .db مفتوحًا وحده وتفترض أن جميع العمليات محفوظة فيه.

1. جهز قاعدة MySQL **فارغة جديدة**، وحدد اسمها في .env وصلاحيات المستخدم عليها.
2. لا تستورد بيانات العرض التجريبية ولا تشغّل db:init قبل النقل؛ أداة النقل تنشئ الجداول بنفسها وترفض قاعدة هدف تحتوي سجلات.
3. شغّل:

```bat
npm run db:migrate-sqlite -- "C:\path\almizan.db"
```

تقرأ الأداة المصدر فقط، وتتحقق من سلامته، وتنقل الجداول داخل معاملة وتتحقق من العلاقات وعدد السجلات. إذا كانت النسخة القديمة تفتقد جدولًا أو عمودًا مطلوبًا ستتوقف برسالة واضحة. هذه الأداة تستخدم node:sqlite المدمج في Node؛ التطبيق العادي لا يفتح SQLite.

قبل الاعتماد على البيانات المنقولة، قارن ميزان المراجعة وكشوف العملاء والموردين والمخزون بين النسختين. لم تُختبر بياناتك الشخصية لأنها غير متاحة في هذا المستودع.

## 7. النسخ الاحتياطي

من شاشة النسخ الاحتياطي تحصل على ملف JSON خاص بهذه النسخة من MySQL، يتضمن الجداول وبياناتها مع بصمة SHA-256. الاستعادة تتحقق من الأعمدة والعلاقات، وتحتفظ بملف أمان قبل الاستبدال، وتلغي جلسات الدخول بعد نجاحها. الملفات القديمة .db ليست نسخًا قابلة للاستعادة بهذه الشاشة؛ استخدم أداة النقل أولًا.

احفظ نسخة خارج الكمبيوتر. ملف النسخ يحتوي بيانات حساسة ولم يُشفّر تلقائيًا. النسخ متسق مع عمليات الكتابة التي تتم عبر التطبيق؛ لا تعدّل الجداول مباشرة أثناء النسخ أو الاستعادة. يستخدم التطبيق قفل كتابة واحدًا لكل قاعدة لضمان الترقيم والأرصدة؛ يتطلب اختبار حمل قبل التوسع الكبير.

## 8. الاختبارات

```bat
npm run lint
npm run build
npm run test:all
```

اختبارات قاعدة البيانات تنشئ وتحذف قواعد بأسماء almizan_test_*، ولذلك تحتاج حساب اختبار له صلاحيات إنشاء وحذف قواعد اختبار. لا توسّع صلاحيات حساب التشغيل المعتاد لهذا الغرض. يمكنك تشغيل الاختبارات في GitHub Actions الذي يجهز MySQL منفصلًا. فحوص Windows في CI تغطي التثبيت والبناء؛ اختبارات MySQL تعمل في Linux.

انظر `MYSQL_VALIDATION.md` لنتائج التحقق الفعلية وحدودها.
